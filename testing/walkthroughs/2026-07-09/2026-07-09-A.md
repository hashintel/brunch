## review-set flow

![review-set presented](<CleanShot 2026-07-09 at 14.58.56@2x.png>)

This is interesting

- the improvised review-set TUI rendering is interesting but wrong
	- we'll need a visual-design session for that
	- it has a lot of repetition of meta/label content
	- it doesn't say anything about edges
- the main issues are however
	- it took quite a long time to infer this
	- in the logic of the v0.x branch of this product, it shouldn't have actually offered this for review, it should have mutated it directly based on the fact that the digest was approved
	
This last point is very interesting, because the structure of a review-set is more specific and rigorous, and suggests that perhaps the "digest" format should already have been leaning more towards this kind of structure, that is not individual nodes and edges, but something more like grouped sections, and picking out more types of nodes, including user stories, theses, and so on, which this pass didn't get

Also interesting: when I accepted teh review, with the comment that the agent had not extracted any thesis or story nodes, nor any edges, it went back and made a second proposal:

![follow-up review-set](<CleanShot 2026-07-09 at 15.10.26@2x.png>)

- this time it created edges as well, seeming to suggest that it just needs to be told explicitly to do this
- it also seems to validate the instinct that a multi-pass operation is a good way to approach it, and perhaps it should be done with parallel sub-agents
