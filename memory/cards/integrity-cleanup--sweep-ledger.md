## Cross-cutting obligations

- Every deletion row runs the out-of-graph-consumer checks before deleting, and reconciles `TOPOLOGY.md` / `treedocs.yaml` references **in the same row**.
- **Pass `rg --hidden` for every consumer grep.** `src/.pi/**` is a hidden path, so plain `rg` silently reports zero consumers for anything under it (found row A1, 2026-08-03: five fixtures read as unreferenced until `--hidden` revealed five importing suites). Rows touching `src/.pi/` — inert tools, unused barrels/wrappers — are exposed to this false negative.
- **`--hidden` is not enough for build output — pass `--no-ignore` when grepping `dist/`, `dist-web/`, or any gitignored artifact.** `rg -g 'dist/**/*.js' <pattern>` returns **zero** for everything, because `--glob` selects within the ignore-filtered file set rather than overriding `.gitignore`. Found row A12, 2026-08-04: the first published-surface sweep reported no `react` import anywhere under `dist/` while `dist/web/components/app-header.js:1` literally begins `import { jsx as _jsx } from "react/jsx-runtime"`. Any row whose oracle is "the published surface" is exposed: the artifact it must read is gitignored by construction. Same failure family as the `rg --hidden` bullet above — a silent zero, not an error.
- **A canonical doc that declares a module live overrides an induction deadness verdict.** Before deleting, read the owning `TOPOLOGY.md`/`README.md` *prose* (not just its layout sketch) and grep active `memory/cards/*.md` for successor frontiers that plan to reuse the target. Found row A2, 2026-08-03: the induction read "retired campaign frontier" as "dead code", but `src/dev/TOPOLOGY.md` + `README.md` declare the same files functional dev/eval primitives and the live `capture-ledger-tracer` card reuses them. Retiring a *plan identity* does not retire the *code* it left behind.
- **A module whose entry is a CLI guard (`import.meta.url` compared against `process.argv[1]`) has no import-graph consumers by construction** — its callers are humans and docs. Grep `docs/praxis/`, `.fixtures/**/README.md`, and `scripts/` for the invocation string before reading reference-count zero as deadness. Found row A6, 2026-08-03: `src/graph/validate-fixture.ts` is invoked by name in `docs/praxis/manual-testing.md` and seven seed READMEs. Same row: **check the deletion list against its own source lens** — `contract-lenses.md:41` had already named `validate-fixture` a falsified target of the induction that produced this row.
- **A test file named after a module does not necessarily test that module — read its imports before treating it as a "solely-owned test" of the deletion target.** Found row A7, 2026-08-04: `src/db/row-schemas.test.ts` imports `connection.js` and `schema.js`, never `row-schemas.js`; it is real `db/schema.ts` coverage (D118-L posture columns, `edges.acknowledged_lsn`) wearing a misleading name, so deleting it with its namesake would have silently dropped table-level coverage. Filename adjacency is not ownership.
- **Run `git log -S` on the target's *exported symbols*, not just its path — removal provenance is the discriminator between "built ahead" and "orphaned by a later decision", and an **active** SPEC decision can be the doc that declares a module live.** Path provenance answers only "when was it born"; symbol provenance also answers "did something once call this, and which frontier deliberately removed the call". Found row A8, 2026-08-04: `git log -S 'renderToonBlock'` showed `src/agents/shared/toon.ts` had a real consumer — the ranked-elicitation-gap render in `spec-context.ts`, the very example D83-L cites for TOON — which FE-1116 deleted when D101-L moved gaps to the session scratchpad. So the module is dead *because a later active decision retired its subject without anyone propagating the change back into the earlier active decision*. That is a third disposition class alongside genuinely-dead (A6's `query-projection.ts`) and pending-consumer (A4/A6/A7): **stale-clause-in-an-active-decision**, which a deletion row cannot close, because striking the clause is a product call for `ln-spec`. Check the target against active decision *text* (`memory/SPEC.md` decision rows **and** the lexicon), not only `TOPOLOGY.md`/`README.md`.
- Intentional topology stubs (`export {}` + design comment) are not deletion candidates on unusedness alone.
- Consolidation rows are behavior-preserving: existing suites stay green, no semantics change rides along.
- Tie-off: `npm run verify:full` (executor seams are touched) and a changeset (`npm run changeset` — the published dependency set changes).
