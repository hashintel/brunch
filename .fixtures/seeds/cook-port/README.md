# `.fixtures/seeds/cook-port/`

The three reversed cook-fixture specs from the main-branch worktree
(`../brunch/src/server/fixtures/cook-fixture-specs.ts`), ported to the
brunch graph model. Development seed data: small, fully-grounded intent
graphs whose point is their *shape* (fan-out / join+gate / halt-isolation).

## Provenance

Source: `../brunch/src/server/fixtures/cook-fixture-specs.ts` (sibling
main-branch worktree) — the `parallelUtils*`, `layeredTodo*`, and
`resilientPipeline*` item/edge arrays plus each scenario's grounding and
design-answer strings, vendored verbatim inside
[`_port-script.ts`](./_port-script.ts).

Each sibling `cook-*/base.json` is generated by `_port-script.ts`
(throwaway data-prep, not product code). Re-runnable from this directory
alone; each run overwrites the sibling base fixtures:

```
npx tsx .fixtures/seeds/cook-port/_port-script.ts
```

## Transformation rules

See the header docstring of the port script for the full mapping. Summary:

- Node kinds map 1:1 (all intent plane, basis `explicit`).
- `term` / `decision` nodes carry the validator-required detail objects;
  slots the source never recorded (rejected alternatives, missing
  rationale) hold the marker `(not recorded in source)`.
- Edge relations → categories: `verifies` → `proof[for]`,
  `constrains` → `boundary`, `refines` → `support[for]`,
  `derived_from` / `depends_on` → `dependency` with endpoints flipped
  (upstream knowledge at the cascade end).
- The `seedClosedSpecFromKnowledge` interview replay has no equivalent in
  the seed contract; its grounding exchange and design answer survive as
  two `context` nodes (source `cook-port-interview`) supporting the goal.
- Deliberately preserved: **no requirement→requirement dependency edges** —
  the slice DAG is plan truth the architect re-derives, not spec truth.

Original item keys are preserved in `source` as `cook-port [<key>]`.
